# Porting rules - Street Rod 2 -> SDL3

Faithful reimplementation of Street Rod 2's **SR.EXE** (1991), VGA 16-colour path, as a **delta port** of
the Street Rod engine (`../../StreetRod/srport/`, tag v0.1.0). Behaviour, timing, integer arithmetic and
visible quirks must match the original. Specs: `../port/spec/*.md` (read `../port/RE_GUIDE.md` first),
`../FORMATS.md`. SR1 facts: `../../StreetRod/port/RE_GUIDE.md`, `../../StreetRod/port/spec/`,
`../../StreetRod/srport/PORTING.md` (rules that are not repeated here still apply: API conventions,
timing, VGA register model, sound/game-flow notes). Never edit `../../StreetRod*` from here.
Ground truth when a spec is unclear: `python ../tools/x86dis.py ../work/SR2_unp.exe dis SSSS:OOOO LEN`.

## Layout (S4.1 skeleton)

```
src/main.c        port args (--game-dir, --scale, --fullscreen, --check, --run-ms), mem_load_exe(),
                  host_init(), ega_init(), game_main()
src/mem.h/.c      real-mode memory: unpacked SR.EXE image at segment 0x1000, DGROUP 0x4E08 (file 3E08)
src/host.h/.c     SDL3 host, unchanged from SR1: window, PIT-rate tick, retrace clock, XT scan codes,
                  mouse, gamepad, PC-speaker model, files (host_game_path), fatal errors, dev aids
src/codeptr.*     far code pointers stored in game data -> C functions (FN_ constants)
src/symbols.h     GENERATED by ../tools/gen_symbols.py from ../port/symbols.csv (654 DS_ globals, 913 FN_)
src/platform/     ega.h/.c plane memory + palette + scan-out; vga.h/.c VGA register model (both = SR1);
                  lib.h/.c LIB1/2/3 directory + pic_unpack (new, SR2 format)
src/game/         game.h, game_main.c = placeholder (LIB1 #0); real game code arrives in S5.x
third_party/nuked-opl3/   Nuked-OPL3 (LGPL-2.1+, LICENSE), compiled as library nuked_opl3, unused until S5.4
```

S5.1 (platform + video) added: `src/platform/{startup,timer,kbd,input,dos,memory,drv_ega,blit,anim_rect,gfx,
screen,lib,textmode}.c`, `platform.h`, `video.h`, `ds_extra.h` (DGROUP offsets that `symbols.h` lacks or names
differently), `modules.h/.c` (hooks into race / sound / game_flow, all stand-ins for now) and
`game/flow_stub.c` (the few game_flow functions the start-up chain needs: `rnd`, `input_reset`,
`wait_click_or_key`, `title_sequence`, empty `hot_data_load` / `hall_load`; S5.2 replaces the file).
Not taken from SR1: `launcher/`. `sound/` was ported in S5.4, `game/*` in S5.2 / S5.3.

Build (MSYS2 mingw64 SDL3, as SR1; put `C:\msys64\mingw64\bin` on PATH or the compiler test fails):
`cmake -S sr2port -B sr2port/build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_C_COMPILER=gcc`.
Headless: `SDL_VIDEO_DRIVER=dummy SDL_AUDIO_DRIVER=dummy SR_SNAPSHOT_DIR=dir sr2port --run-ms 600`
writes `snapNNNN.bmp` frames (also `SR_KEYS`, `SR_SNAPSHOT_MS`, see `host.h`).

## SR2 addresses and memory

* `SR.EXE`: EXEPACK (MSC 6.0), 264 468 -> 288 912 bytes (0x46890) unpacked, 2721 relocations, entry 34b0:0018.
  `mem_load_exe` unpacks in C (the SR1 unpacker works unchanged) and checks DS:0214 "nomouse", DS:021C "demo".
* File segment SSSS -> `SEG(0xSSSS) = 0x1000 + SSSS`. **DGROUP = file 3E08** (`DGROUP_FILE_SEG`, SR1 3E96);
  `DS:xxxx` = image `0x3E080 + xxxx`. `HEAP_BOTTOM = DGROUP + 0x1000`. Main code segment is `0001`
  (SR1 `0000`+0x10 style: SR1 `0000:6476` is SR2 `0001:63e0`); game code also in `1a21`, `2925`, `0dcb`.
* Symbol names: `DS_x`, `FN_x` from `src/symbols.h` (names are the SR1 names where the function matched).
  There are no CS_ variables in SR2's table. Regenerate: `python tools/gen_symbols.py` (repo root).
* DGROUP anchors: live palette `DS:1DA6` (17 bytes, identity at start-up), pic run tables `DS:4B72` counts /
  `DS:4B82` values, driver vector table `DS:A0AE`, `snd_state` `DS:004E`, `snd_device` `DS:0050`,
  `road_mode` `DS:ADD6`, library bases `DS:B8CA` / `DS:B8D6`.

## Picture libraries (`platform/lib.c`, FORMATS.md)

`u16 count`, `count` x **28-byte** records `{u16 w, u16 h, u8 depth (4 = 16 colours, 2 = CGA), u8 masked,
u8 tokens[16], u32 offset (from the end of the directory), u16 size}`; packed data starts with 0xBC.
Raw size = w*h*depth/8, planar (4 planes of h rows of w/8 bytes, MSB left). `lib_read_dir` 1a21:6432 turns
each record into a 0x22-byte entry (`+1C` = FF, `+1E/+20` = 0). Library ids: LIB1 1.. (4 pictures, base
index 0), LIB2 1000.. (212), LIB3 2000.. (83). **`pic_unpack`** (26b3:000c): `00 00` / `FF 00` are the
literal bytes tokens[0] / tokens[1] (SR1 read them as a 1-byte run); no count is returned. Start-up screens
use the identity palette until a screen calls `pal_load` (`../port/spec/video.md` "Palettes").

## Graphics driver: 20 slots

The driver vector table is **20 far pointers at `DS:A0AE`** (SR1: 15 at `DS:78A2`), template EGA/VGA at
`DS:7B38`; `ega_install_vectors` copies 0x28 words. Slots 0-14 as SR1 (blit, blit_shifted, blit_masked,
draw_text, draw_cursor, copy_page, recolour_rect, pal_black, pal_normal, anim_step, blinds, slide_sprite,
line, hspan, fill_rows); slots 13/14 now point into race_render (`0dcb`). New: **15** pixel shrink, **16** and
**19** road helpers (`0dcb`), **17 ega_set_colour** (2f32:1932), **18 poly_fill** (33f8:01ca). Register every
target with `codeptr_register(FN_x, fn)` and call through typed `drv_*` wrappers as in SR1. Descriptor
(`Desc`) is **0x12 bytes** (`w, h, size, FarPtr planes +6, FarPtr mask +A, stride +E, type +10`; SR1 0x30
with planes at +24); static page descriptors in segment 371c. Screen pages at A000:0000/2000/4000/6000 as SR1;
cursor bank plane stride 0x480 (SR1 0x600). Spec: `../port/spec/video.md` sections 2-3.

## Sound: AdLib + speaker

SR2 has two devices (`DS:0050`: 0 AdLib, 1 speaker, 666 unset); `adlib_detect` 1733, then
`sound_options_menu` 01ea. All effects go through a **25-slot far-pointer table `DS:BB8C`** filled by
`speaker_sound_init` (from `DS:530A`) or `adlib_sound_init` (from `DS:73C2`). AdLib: OPL2 via port `DS:7830`
(0x388), 18 operators, 11 voices, timbre bank `MSR.SND` (30 timbres incl. effects), songs `*.MUS` (percussive
mode, tick 240) played by `mus_tick`; Nuked-OPL3 renders the register writes (`tools/sound/oplrender.c`
shows the offline use). Music timer ISR `mus_timer_isr` 2f1b:00cb owns INT 8 while a song plays and chains
the game tick (68.6 Hz at tempo 120, 60 Hz at tempo 60): the host timer must model that. No Tandy/PCjr sound.
Spec: `../port/spec/sound.md`.

**S5.4 (src/sound/, `sound/sound.h` is the API, `game/snd.h` the include of the game code):** `slots.c` the table
`sound_vec(k, arg)` (= `(*DS:BB8C[k])(arg)`, far pointers resolved through `codeptr`; every slot routine is registered by
`snd_register_codeptrs`), music_stop / resume, the sound parts of `timer_isr` / `race_isr` / `race_isr_enter` / `race_isr_leave`
(`modules.snd_*` hooks); `spk.c` speaker (SR1 effects + table-driven sequencer, song data stays in DGROUP); `adlib.c` OPL2 driver;
`mus.c` MSR.SND bank, `.MUS` interpreter `mus_tick`, playlists and the music ISR; `adfx.c` AdLib effects and engine drone.
PORT notes: the AdLib driver state (operator parameters, F-number rows, caches) is C state of `adlib.c`, the bank and songs are C
buffers; `adlib_detect` always succeeds so the sound menu is offered as with a card; the speaker busy-loop effects use the SR1
timing constants. `host_opl_write` is stamped on the emulated timeline and the OPL3 chip is rendered in the same audio callback
(output rate 49716 Hz = the OPL2 rate). Dev aid: `SR_AUDIO_WAV=file.wav` (alias of SR_AUDIO_DUMP) writes the mixed mono output.
* **Game tick under AdLib music (U7 item 6, faithful):** the music ISR (`mus.c: mus_timer_isr`) owns the host tick at the song's
  rate (D = 0x1234DC / (tick_beat * tempo / 60) = 2485 at tempo 120) and calls the game ISR when its 0x4000 accumulator is <= 0,
  remainder discarded: 68.6 Hz at tempo 120, 60 Hz at tempo 60 (72.8 Hz when no song plays). `platform/timer.c` therefore sets
  its ISR with `snd_int8_set` (chained pointer while the music ISR is installed), not `host_set_tick_handler`.
* **Playlist stall (PORT: verify U5):** when a song ends the next song's first delay (0) is returned raw, the countdown wraps and the
  next `mus_tick` runs 65 536 interrupts later (136 s at 480 Hz), as the code does (sound.md 7.2 item 3).
* Fixed in game code: the text-edit reject beep called slot 15 (the crash) instead of slot 12 (`ui_edit.c`);
  `race_isr_enter/leave` now set / clear DS:A2B2, 1F7C, 1F78, 72E2, 72E0, 7BA2 as the original (in `snd_race_enter/leave`).

## Road modes (`DS:ADD6`)

0 town cruise, 1 street drag race, 2/4 Grudge Night drag strip (breakout run / rounds), 8 Aqueduct race
(separate renderer), 0x10 Mulholland (hillsides, truss bridges, guard rails). Shape sets come from
**`SR2_SHP`** (26 span-shape sets, directory at DS:80A2, loaded per mode by `shp_load_set` into a second
arena). Spec: `../port/spec/race_render.md` 1.1; formats in `../FORMATS.md`.

## How to port a function from a delta spec

1. Look the function up in `../port/sr2_sr1_matches.csv`; its class and the spec section say what to do.
2. **same / "= SR1 ..." line**: reuse the SR1 C file (`../../StreetRod/srport/src/...`) and only remap
   `DS:` offsets (`../port/spec/video.md` section 6 "Regular DS remap blocks"; other modules list their
   own remaps), file segments (`SEG(0x0e6c)` -> new segment) and descriptor offsets. Keep the SR1 names.
3. **changed**: start from the SR1 code, apply exactly the listed difference ("Delta:" / "SR2:" text of the
   spec) and nothing else; check ambiguous points with `x86dis` against the SR2 address.
4. **new**: write it from the spec section; where the spec is silent, read the disassembly. Mark any
   deliberate deviation `PORT:` with a reason.
5. Name functions as in `symbols.csv`, put `/* SSSS:OOOO */` in the header comment, use `DSB/DSW/DSS/DSL`
   with `DS_` names (never shadow game state in C variables), `FN_` + `codeptr_register` for functions
   whose address is stored in game data. Busy-wait loops call `host_pump()` every pass; divisions go
   through `div32_16` & co.
6. Verify with the headless run (`SR_KEYS`, snapshots) and queue a **U-check** for the user: visual checks
   are the user's job, so write the frames and ask what they see.
7. Not ported (VGA only): CGA, Hercules, Tandy driver branches (the spec lists them as "not ported").

## Faithful only

No enhancements (resolution, widescreen, new options): add an idea as a row to PLAN.md "Enhanced backlog".
The port's own additions are marked `PORT:` in the code. Larger ones:

* `platform/textmode.c`: the 80x25 text mode of the two start-up menus (video options, sound options) is drawn
  with the game's own 8x8 font into a 640x200 frame (`HOST_FRAME_MAX_W` is 640); keys come from the XT stream.
  The detection (VGA assumed, EGA runs as VGA, CGA / Hercules / Tandy refuse) replaces the BIOS probes.
* `platform/dos.c`: the far heap is not the MSC 6.0 allocator; each `_fmalloc` is its own DOS block in `mem[]`
  (the game cannot observe the difference); `_dosmaperr` stores errno = DOS code.
* `modules.c`: function-pointer hooks for the sound ISR parts, the race physics step and `fatal_message`.
* `game/flow_stub.c`: everything game_flow-owned that the start-up chain calls, plus an idle loop with the
  pointer movement of `ui_wait` so the pointer / mouse / keyboard ISR model can be tried.
